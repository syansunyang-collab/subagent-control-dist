# AGENTS 创建与维护

> 职责：指导主代理按宿主加载机制创建、审查和精简项目入口。
> 真源：AGENTS 专项写作方法；通用规则质量判据归 rule-authoring 技能。
> 读取：命中读取

## 从受众与加载开始

面向没有历史会话记忆、具备推理能力的代理写作。区分它已获得的当前上下文与需要主动取得的项目事实，不依赖作者记忆或旧会话决定。

先确认目标宿主、入口位置和实际可见内容。复用已有有效证据；缺少依据时，按需核对本机版本、官方文档、配置或实现。区别启动加载、每轮可见、主动读盘、reload 更新和历史消息压缩。技能目录可见不等于正文已加载，文件存在不等于模型已读到，磁盘修改不等于现有会话更新。

多宿主共用入口时保留共同项目约定，把某一宿主的恢复补偿放到该宿主的适配入口。加载机制未查明时说明假设与影响，先处理不依赖该假设的内容，不猜测加载行为。

## 确定内容归属

创建时从项目事实与真实工作需要组织入口；维护时通读当前全文，对照直接依赖判断每段的用途。不套用固定章节模板，也不照搬另一个项目的目录、工具或审批流程。

入口保留高频且能改变行动的项目约定：目标与证据、取证与推进、协作、验证、工作区与授权。高代价但低频的安全边界可保留。删减前核对其行为是否仍有承载方，尤其是验收主体、写域释放和失败出口。

专项步骤放入已有 workflow、policy 或技能；工具参数、模板与结果读取方法放入工具面。已有承载方时删除副本，不再建平行协议。常识、失效机制和无行为增量的解释可以直接删除，不必每条都搬到新文件。

审查读取成本时计算整个调用路径：入口减少文字但迫使每次多读几个文件，不算有效精简。移入工具说明也不自动减少模型上下文。

## 写成可执行入口

用短句说明动作、对象和用途。需要发现资源时写“做什么，读取哪个文件或使用哪个技能”；已有上下文直接复用。具体章节、字段仅在定位确有帮助时使用，避免重复回指已加载的通用纪律。

按需读取与补证保留代理判断空间。不要为消除措辞弹性而追加条件枚举、例外清单、每轮检查或固定填表。权限、不可逆动作与验收硬约束仍写清边界和出口。

例如：

- “按需读取项目材料，复用当前上下文中的有效内容。”
- “需要恢复工程进展时，读取项目状态文件。”落盘时使用目标项目真实存在的文件名。
- “返回证据后判断当前假设，继续试错或收口。”由本层说明证据用途，工具负责读取方法。

文档中的“固定读取”标签不是加载机制证据。取消重读要求时检查读取约定与宿主提醒；调整入口字段时检查实际消费方；允许只读共享时继续保护正在执行或审查的输入与产物版本。

## 修改与验证

按已确认范围修改；低频细则下沉前确认现有落点和发现入口。检查实际 diff、直接引用及派生副本，保留任务前无关改动。验证针对本次实际修改；文档中记载的命令不是当前执行清单，纯入口写作无需运行未改代码的测试。复用目标项目现有验证工具，不为了规则整理新建脚本或门禁。

本仓规则的引用与地图检查使用：

```bash
python -B ops/tools/reference_resolution_check.py --source AGENTS.md
python -B ops/tools/cockpit_map.py --lint
```

外仓采用其已核实的入口与检查方法，不照搬本仓命令。无检查工具时人工核对引用和差异并披露限制。

按 rule-authoring 检查本次修改，复用已有有效证据；具体疑点需要独立判断时，再针对该问题安排检查。测试场景只覆盖修改内容，说明实际采用的检查方法。正文缩短不能代替行为证据，也不能当作实际 token 节省。

交付说明修改了什么、细则由谁承载、验证结果与未验证项。机制不确定或证据不足时补齐具体缺口，不通过增加强制读取要求掩盖问题。
