# 按模型指南调整提示

> 职责：将模型官方指南转成适合当前任务与读者的提示改动。
> 真源：官方指南适用性核对、候选改动与对照验证方法
> 读取：命中读取

## 取用步骤

1. 明确要改变的行为、模型型号与版本、运行模式和提示读者。复用当前有效的来源与加载证据。
2. 阅读对应官方段落的上下文，区分默认行为、推荐示例和适用条件。型号特例归该型号；示例中的自主程度按应用目标选择。
3. 对照现有提示，选用直接影响目标的动作，合并重叠要求，用少量完整句子形成候选。改动说明分别标清任务要求、对应型号原文支持和本次工程取舍；同一目标可在不同型号上共用适用句。
4. 用同一组代表输入对照旧稿和候选稿，观察理解、行动、验证和交付的实际差异。先复用已完成的有效检查，再针对新疑点验证。

只有指南与原文对照时，输出候选及来源；取得实际运行证据后，再说明行为或成本是否改善。原文及版本信息存入研究资料，运行提示只保留被采用的指令。

## 写法示例

目标是让理解分歧及时可见时，可写：

> 动手前说明对目标的理解；有会影响结果的分歧时确认，再继续工作。

官方示例中的完整审批、委派和报告流程按本次目标选取，候选保留需要的动作。

## 行为调校

| 要解决的问题 | 取舍方法 |
| --- | --- |
| 隐藏理解分歧 | 表达目标理解与采用的假设；用户回答会改变后续工作时提问。讨论、评估与实施按当前请求区分 |
| 反复询问与重新规划 | 复用已经确认的目标和决定，推进当前已明确的工作 |
| 过度验证 | 按改动完成相关检查；出现新改动、失败或未解决疑点时再扩大或重复验证 |
| 长任务进度失真 | 将进度与工具结果、产物及既定验收条件对应；独立验收是否适用按任务与型号建议选择 |
| 说明难懂 | 先给结果，补足理解所需的依据与影响；使用完整、通俗的表达 |
| 提示随着模型升级膨胀 | 对照新模型默认表现，优先删除失去作用的旧句，再决定是否需要新增指令 |
| 时间与缓存 | 分开静态规则和动态事实；核对变化位置、宿主请求组装与供应商缓存边界，再判断缓存影响 |

理解复述交付的是目标、假设和决定的摘要。内部逐步推理的回放不是任务交付要求。

## 型号适用性示例

| 官方说明 | 可支持的调整 | 适用边界 |
| --- | --- | --- |
| GPT-6 Astra：小任务可能出现超出需要的测试；完成相关检查后，新增改动、失败或未解决疑点才扩大验证 | 减少重复检查，保持任务要求的验证 | 不能据此推导子代理回执自动等于验收通过 |
| Claude Fable 5：简短方向通常足以引导行为；长任务以工具结果核对进度，独立上下文验收通常优于同一代理自我批评 | 简化过程规定；为长任务选择适当验证方式 | 不是所有任务都增加验收代理或周期检查 |
| Claude通用指南中的Opus 5特例：模型默认自验较好，旧验证指令可能导致过度验证 | 迁移到该型号时评估移除旧自检催促 | 该特例不转移给Fable 5或所有Claude型号 |

以上是版本明确的参考案例。使用其他型号或新版指南时，按其原文重新核对适用条件。
