# rule-authoring 触发判例

> 职责：模型行为规则与模型接口文案的触发回归基线。
> 真源：本技能正反判例及行为判例
> 读取：维护读取

## 正判例（该触发，用户真实话术）

1. "在runtime-tools政策里加一条工具使用规则。"
2. "改一下AGENTS里派发口径那段。"
3. "这条协议写得太散了，按写作标准重写。"
4. "帮我审查这批规则改动符不符合写作门。"
5. "重写.mjs里的工具description，让模型知道什么时候用。"
6. "参数说明要区分target_paths和scope写入授权，省略时会怎样也写清楚。"
7. "改seed模板和发给模型的失败提示，让它知道补哪个字段。"
8. "终态通知迟到时别再让模型重复读取结果，调整通知文案。"
9. "给新项目创建AGENTS.md，保留高频约定，其余按需发现。"
10. "按实际加载机制维护AGENTS，别让代理反复读已知文件。"
11. "参考这个模型的官方指南，调整提示里的询问和验收要求。"

## 反判例（近失配不该触发，注明去处）

1. "新建一个技能。" → skill-authoring-governance。
2. "写一份验证报告到notes。" → writing-governance。
3. "写决策记录说明这次改动。" → change-rationale。
4. "整理会话记忆。" → 记忆内容（无规则写作技能）。
5. "只调整工具内部排序算法，不改变模型可见接口或说明。" → 纯实现（无规则写作技能）。
6. "把面向人的设置窗口按钮标题改短。" → 普通UI文案（不触发模型规则写作）。
7. "只下载模型官方指南，不修改提示词。" → research 外部调研（不触发规则写作）。

## 行为判例

1. 任务提示："AGENTS、工具说明与终态通知都有派发要求，请整理各自职责。" / 期望首动作：核对实际可见文本的受众、时机和真源。 / 期望产出：全局协调、调用合同与本次下一步分别落位，不把整段规则复制到工具。
2. 任务提示："修改源码中的参数说明与错误提示。" / 期望首动作：读取实际schema、默认行为和返回出口，按模型接口文案判据书写。 / 期望产出：工具侧自然语言说明，不套WHEN/MUST标签；只改纯实现时不触发本技能。
3. 任务提示："审查schema和description都出现同一取值范围是否重复。" / 期望首动作：判断是否各有消费用途及是否共用真源。 / 期望产出：区分必要一致投影与独立维护或无信息重复。
4. 任务提示："创建或精简AGENTS，宿主已提供加载证据。" / 期望首动作：复用证据，核对入口全文与项目事实。 / 期望产出：可落盘入口及必要联动；保留高频指令，不新增每轮表格、必读链或宿主调查。
5. 任务提示："按已提供的官方指南，为两个模型分别调整同一份旧提示。" / 期望首动作：核对指南的适用型号、任务目标和实际读者。 / 期望产出：适配后的提示与来源依据；区分通用建议、型号特例和应用选择，保留仍有效的验收要求。
