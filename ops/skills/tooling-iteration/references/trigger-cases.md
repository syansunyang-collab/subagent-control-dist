# tooling-iteration 触发判例

> 职责：本技能触发的回归基线，竞争性触发验收与漂移修订以此为准。
> 真源：本技能触发判例（正判例、反判例、行为判例）
> 读取：维护读取

## 正判例（该触发，用户真实话术）

1. "dispatch_prepare 又报错了，帮我修。"
2. "async collect 的行为跟文档说的对不上，登记修一下。"
3. "async wrapper 把能用的产物标成 failed 了。"
4. "这个校验器老是误报，迫使我手工绕过。"
5. "cockpit_map 出错了，工具病登记一下。"

## 反判例（近失配不该触发，注明去处）

1. "这个业务任务失败了。" → 任务内容问题，非工具病（无技能）。
2. "给这个工具加个新功能。" → 无观测摩擦的功能请求，转 owner 拍板（无技能层触发）。
4. "这个偶发环境抖动不复现。" → 一次性环境 glitch（无技能）。
5. "把这个工具坏了的问题投给外部模型看。" → external-review-rescue。

## 行为判例

1. 任务提示："dispatch_prepare 行为与文档不符。" / 期望首动作：当轮先落盘登记到 notes/tooling 目录。 / 期望产出：issue 文件 + 分诊闭集定类 + 回归用例 + 验证关闭。
2. 任务提示："校验器误报迫使手工绕过。" / 期望首动作：登记 + 按分诊闭集定类。 / 期望产出：最小修 + 用例名可追溯到 issue，不顺手重构相邻逻辑。
