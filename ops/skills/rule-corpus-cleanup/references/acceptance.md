# 验收清单

> 职责：规定规则语料清洗验收清单。
> 真源：规则语料清洗完成判据和交付报告要求
> 读取：命中读取

> 用途：第 4 步收尾时逐项打钩；全部通过才算清洗完成。任何一项不过，回到对应步骤补课，不带病交付。

## §1 完成判据

| # | 判据 | 怎么验 |
| --- | --- | --- |
| 1 | 修改得到验证 | 只测试验证本次修改部分，复用已有有效结果；修改引用时核对对应引用 |
| 2 | 清理目标落实 | 核对本次修改是否处理了已明确的问题，列出尚未处理的内容 |
| 3 | 判据一致 | 本次修改采用一致的写作判据 |
| 4 | 已发现问题有处理结果 | 本次 findings 已修复或说明尚未解决的原因，复用已有检查结论 |
| 5 | 言行对账零虚报 | 每个提交信息的声称与 git diff 对账通过；发现过的虚报已在后续提交更正记录 |
| 6 | 残值安置有记录 | 每个被整删的机制都有一行答案：它防的事现在由谁防（真源指针 / 已机械化 / 确认为零残值） |
| 7 | 契约面零损 | 字段名、枚举值、标题锚点、机器读取块与清洗前一致，或变更有显式的消费方同步记录 |
| 8 | 指令可执行 | 核对修改后的指令是否能够引导完成目标动作 |

## §2 交付报告必含

1. 清洗范围与提交链（基线提交..收尾提交）。
2. 已处理的过度要求与尚未解决的内容。
3. 实际发现的问题与处理结果。
4. 残值安置表。
5. **审查边界声明**：审了什么面、没审什么面、用什么方式审的（静态/实弹）。没有边界声明的报告视为不诚实报告。
6. 如报告体积变化，只作为事实，不作为质量结论。

## §3 不达标处置

修复本次修改中发现的问题，核对修复结果，复用其他有效证据；无法解决时列明缺口，涉及取舍时交用户裁决。

## §4 收口

本次修改达到明确目标、验证结果能够支持结论时收口。尚未解决的内容明确列出，不追加固定的收尾验收轮次。
