# writing-governance 触发判例

> 职责：写作分流与项目文档写作的触发回归基线。
> 真源：本技能正反判例及行为判例
> 读取：维护读取

## 正判例（该触发，用户真实话术）

1. "这批同时改规则和README，先判断分别走哪个写作门。"
2. "工具源码里有给模型看的说明，也有普通注释，先区分各自适用什么写作要求。"
3. "写个README或验证报告，要符合仓库规范。"
4. "这批交付有操作文档、工具文案和临时笔记，帮我按读者分流。"
5. "这份handoff文档怎么写才符合判据。"

## 反判例（近失配不该触发，注明去处）

1. "创建一个新技能。" → skill-authoring-governance。
2. "把整套规则语料清洗去防御。" → rule-corpus-cleanup。
3. "按规则写作原则修改AGENTS中的派发约定。" → rule-authoring。
4. "重写工具description，让模型区分目标路径和写入授权。" → rule-authoring。
5. "只优化工具内部排序算法，模型看到的接口和文案不变。" → 纯实现（无写作技能）。
6. "记个临时草稿笔记，不提交的。" → 一次性scratch（无技能）。

## 行为判例

1. 任务提示："一批文件中混有工具参数说明、README和实现代码，判断写作要求。" / 期望首动作：按内容功能和受众分流，不按扩展名。 / 期望产出：模型接口文案走rule-authoring，文档走文档判据，纯实现不进入写作门。
2. 任务提示："写验证报告。" / 期望首动作：读取document-writing判据。 / 期望产出：文档及落盘自检。
