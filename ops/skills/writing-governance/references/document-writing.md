# 文档写作判据

> 职责：规定控制面规则以外的仓内书写（README、PROJECT、handoff、报告、rationale、notes 沉淀）的写作判据与落盘自检。
> 真源：本文件只列文档特有判据；与规则写作共用的通用原则按 `ops/skills/rule-authoring/SKILL.md` §1 执行
> 读取：命中读取

## 通用原则的适用映射

`ops/skills/rule-authoring/SKILL.md` §1 中下列原则对文档同样生效，判据以该文件为准：唯一真源（§1.1）、按需与边界（§1.8）、指针约定（§1.11）、文件自足（§1.15）、技术语调（§1.16）、格式规整（§1.17）。标签纪律、增量门禁、出口必备等门禁类原则不适用于文档。

## 文档特有判据

### D1 受众先行

动笔前确定受众；任务没交代时按「懂这个领域、但不了解本项目细节的人」写。受众决定展开深度：给接手者的 handoff 写到可执行，给未来维护者的 rationale 写到可追责，给首次使用者的 README 写到可复制粘贴。

### D2 结论先行

第一段回答读者最想问的问题（结果是什么、能不能用、修没修好），支撑细节与过程在后。读者读完首段就能决定是否继续读。

### D3 无元信息

不写「这份文档怎么被生成」：不写按谁的要求做、用了哪个方案讨论过程、为什么这样设计的对话背景。交付物自身需要的信息（版本、依赖、前置条件、使用说明）不算元信息，照常写。设计理由有正式落点（`docs/decisions/change-rationale/`），不散落在交付文档里。

### D4 无对话腔

不用第一人称；不出现对读者的称呼；不用「不是 X 而是 Y」的对话式对比强调。UI 控件文字只承担功能，不解释设计理由。

### D5 事实可核

路径、命令、字段、数字写全写准，可复制执行；声称的每个结论有证据落点（命令输出、diff、报告路径）。相对日期转绝对日期；版本与环境依赖写明。

### D6 类型必备件

| 文档类型 | 必备件 |
| --- | --- |
| README / 安装说明 | 包含内容、不包含内容、安装步骤、验收命令（纯净度检查先于工具运行） |
| handoff / 交接书 | 每条含问题描述、修法、验证办法；通用回归命令；执行状态标注（防重复执行） |
| 验证 / 审查报告 | 结论、证据（命令与输出关键行）、覆盖面声明、未覆盖项披露 |
| rationale | 按 `ops/skills/change-rationale/SKILL.md` §4 必填字段 |
| 状态文件 | `STATUS.md` / `ROADMAP.md` 由 `state_checkpoint.py` 渲染，不手写 |

## 落盘自检

落盘前逐项过，命中即改：

1. 首段是否回答了读者第一个问题。
2. 是否含第一人称、对读者的称呼、元信息、设计理由散文、对话腔对比强调。
3. 路径与命令是否可复制执行；引用的文件是否真实存在（治理文件跑 `python -B ops/tools/reference_resolution_check.py --source <file>`）。
4. 相对日期是否已转绝对；类型必备件是否齐全。
5. 与既有文档是否重复承载同一事实（重复则收敛为指针）。
