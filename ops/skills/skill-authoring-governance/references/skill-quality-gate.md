# 技能质量门

> 职责：规定技能的增量验证、语义审查与质量结论。
> 真源：本技能质量判据与证据选择
> 读取：命中读取

## 验证范围

只验证本次修改：触发词改动验对应触发，判定核心改动验该判据，纯措辞、路径或排版改动核对差异。复用前轮机械结果、未改判例结论和同批已验证资源等有效证据，不因收尾轮次或报告数量加测。

质量包含机械合法、行为有效、治理可维护三层；脚本结果只是事实，不替代语义结论。

## 机械校验

修改元数据、目录结构或资源引用时运行：

```powershell
python -B ops/skills/skill-authoring-governance/scripts/validate_skill_structure.py <skill-dir>
```

检查项由该脚本维护：入口与首字节 frontmatter、必需字段及格式和值域、description 长度、非空正文、支持目录、入口资源引用、portable 的仓内越界引用、`references/trigger-cases.md` 的「正判例」「反判例」两节非空、本机绝对路径与来源体系名。

BLOCK IF: 机械校验失败未修复。出口：按错误修复后复验；授权或输入不足时说明缺口，交用户决定。

## 语义审查

按 `ops/skills/skill-authoring-governance/references/skill-authoring-model.md` 核对结构、体量、触发描述与自足性；通用写作判据用 `ops/skills/rule-authoring/SKILL.md`。重点判断：

- 触发与反触发能否区分任务类，工作流所有权是否清楚。
- 首动作、输入和操作前提是否足以启动；步骤能否得到具体产出。
- 资源是否在正确时机读取，验证证据与失败恢复是否可执行。
- 副作用是否有授权边界、何时停下或询问是否明确，内容是否含敏感信息。
- 内容是否重复已有技能、保存一次性状态，入口是否变成资料堆。

只有命令清单或格式合规不足以证明行为有效。发现缺口按下文四类结论处理。

## 竞争性触发验收

触发取决于全技能清单中的相对匹配。本次改变触发行为且已有证据不足时，给验收方全部技能的 name + description，以及打乱、不标来源的受影响判例话术。收到逐条命中判断后，再对照本方保存的期望：正例命中目标技能，反例命中指定去处或无技能。错配时补齐语言、前置区分词或明确反触发，改后只重验受影响判例。

BLOCK IF: 给触发验收方透露来源技能或期望答案。出口：弃用受污染结果，以未接触答案的上下文重验；不可用时说明该证据缺口。

## 行为证据选择

**干净上下文验收：** 尚有具体引导行为待验证且获准独立取证时，让不继承父线程的执行者仅凭技能路径、真实或最小任务、必要原始材料和写入边界执行，记录读过的资源、决策、卡点与产物。主审查者核对首动作、路由、边界和结果，区分技能表达缺陷与输入、工具或任务设计问题；前者修正文，后者修验收条件，再验受影响部分。结论标注「独立上下文实跑」及证据位置；未做则说明原因与影响。

BLOCK IF: 把验收子代理回执直接当作通过。出口：主审查者核对执行证据后给出质量结论。

**主代理保底演练：** 选择自行验证具体行为时，用真实或最小任务及明确边界，从 description 判断、入口首动作、资源路由走到最小产物，记录关键决策与偏离；技能表达缺陷先修后重演。结论标注 `证据强度: fallback_self_run`，与独立实跑区分。证据足够即收口，未采用的方法不自动转为后续任务。

## 质量结论

| 结论 | 含义与动作 |
| --- | --- |
| PASS | 可用，引用证据收口 |
| PATCH | 主体可用，列出精确局部修补项 |
| REWRITE | 结构方向错误，重写入口或资源分层 |
| REJECT | 不应成为技能，改放记忆、文档、笔记或资料镜像 |

只输出三项：**结论**（四类之一）、**采用的证据**（实际结果、来源与证据强度）、**必须修补项**（无则写无）。未解决或未验证内容及其对结论的影响随对应项说明。
