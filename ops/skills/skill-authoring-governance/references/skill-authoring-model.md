# 技能创建规程

> 职责：规定技能合同、加载结构、指令粒度和资源分层。
> 真源：本技能的创建规程
> 读取：命中读取

目录：读者 · 技能合同 · 三级加载 · description 与判例 · 元数据与入口 · 自由度匹配 · 资源分层与路由 · 自足性。

## 读者

面向聪明但失忆的新员工：推理能力满格，本任务记忆为零。

- 判断层假设聪明：只写模型推不出的项目特定决策，省去常识、背景与设计辩解。
- 事实与操作层不依赖历史记忆：写全命令、输入来源、参数填法和前提；任务值取当前事实，复用已有上下文与工具说明，按需取证，术语首次出现即定义。

## 技能合同

重操作只填以下八项，用自然语言写决策，不再拆前置表。归属与扫描方法见 `ops/skills/skill-authoring-governance/references/skill-governance-routing.md`。

```yaml
技能名与路径:
触发:
反触发:
首动作:
资源路由:
验证证据:
相邻技能与归属判断:
需要用户决定的事:
```

首动作写输入与前提，资源路由写读取时机及产出，验证证据写预期结果与失败处理。副作用及待授权动作归入用户决策；无待决项写「无」。已知事实直接引用。合同确定后、写 frontmatter 前先定 `portability`，它决定本文「自足性」走哪一档。

技能目录内 Markdown 合计建议不超过 15KB（按 15000 字节统计，脚本与 assets 另计）；超过时把预计体量及理由写进「技能名与路径」。按内容需要保留资源，不为凑预算压缩有效判断。

## 三级加载

| 层 | 装什么 | 限制 |
| --- | --- | --- |
| name + description | 常驻的触发合同 | 全部技能共享约 8K 字符预算；description ≤1024 字符 |
| SKILL.md 正文 | 触发后的首动作、路由、共享事实和高优先级约束 | 上限 500 行，本仓建议 150 行以内 |
| references / templates / scripts / assets | 按需读取或执行的细节 | 单个 reference 超过 100 行时加目录 |

从入口到资源只走一跳：入口直接点名所需资源，把长背景、原始摘录和案例库放到合适载体。

## description 与判例

把 description 写成第三人称触发合同：前置关键用例和触发词；显式排除共享词汇的近失配场景并指出去处。触发词语言与用户判例一致，中文话术包含中文关键词，混合团队覆盖中英触发词。

先把判例写入目标技能的 `references/trigger-cases.md`，再写 description 和最小正文，并逐条对照自查 description 能否命中正判例、排除反判例：

- 正判例使用真实口语；反判例逐条注明应命中的技能或「无技能」。单域小技能正反各 2–3 条，多域技能（需要按域拆成多个 reference 的）各 5 条以上。
- 行为判例 2–3 条，包含任务提示、期望首动作和期望产出形态。
- 判例与正文同批维护，作为后续回归基线。本技能实例见 `ops/skills/skill-authoring-governance/references/trigger-cases.md`。

## 元数据与入口

frontmatter 从文件首字节开始，正文非空。字段用途和取值如下：

| 字段 | 用途与取值 |
| --- | --- |
| name | 技能名；小写字母或数字起首，仅含小写字母、数字、连字符，≤64 字符 |
| layer | 归属层；orchestration 或 business |
| domain | 能力大域；格式与长度同 name |
| capability_group | 业务或编排治理主分类；格式与长度同 name |
| portability | 自足性档位；portable 或 repo-bound |
| description | 自动选中技能的触发依据，按上节编写 |

用元数据明确归属，供地图与批量管理读取；用「职责 / 真源 / 读取」说明正文执行语义。入口保留路由、安全边界、验证和失败恢复，细节按下表下沉。

## 自由度匹配

| 地形 | 指令粒度 |
| --- | --- |
| 窄桥：脆弱操作、仅一条安全路径，如迁移或注册链 | 给确切命令、文件和允许改动范围 |
| 开阔地：多条路径可达，如审查与治理判断 | 给判据，留现场选择空间 |
| 介于两者：有偏好模式、允许变体 | 给模板或带参数脚本，标出可调整处 |

自由度管步骤松紧，完备度管事实齐全。即使高自由度也写明输入来源、输出要求和验证方式；固定接口写准确，项目路径与检查依现场选择。

好例：落盘后运行 `python -B <校验脚本> <目标>`，非 ok 输出先修复再继续。
坏例：「必要时运行相关校验。」——没有给出判定、命令或目标。

## 资源分层与路由

| 目录 | 内容 | 何时使用 |
| --- | --- | --- |
| references | 长规则、领域知识、审查准则、字段说明 | 需要额外判断依据时读取 |
| templates | 提示词、报告或配置骨架 | 生成固定结构产物时使用 |
| scripts | 确定性检查、转换、探测、格式验证 | 取得可重复机械证据时运行 |
| assets | 图片、字体、样例、二进制模板 | 生成或转换产物时使用 |

资源必须被路由点名：写清触发条件、读取哪个文件、读后产出什么；多域技能按域拆资源，只读命中的域。对脚本区分「运行以取证」与「阅读以了解算法」，确定性操作优先用已有脚本。

好例：「审查质量时读取质量门，给出质量结论。」需要标注主体与动作时写成行首标签：`WHEN:` 触发条件、`ACTOR:` 执行主体、`MUST:` 必须动作、`INPUT:` 必须读取的输入、`OUTPUT:` 必须产出；`BLOCK IF:` 写阻断条件并带出口。

## 自足性

把会搬到其他仓库或供无本仓上下文代理使用的技能标为 portable；绑定本仓工具链、路由或治理结构的标为 repo-bound。

两档路径都使用正斜杠和可迁移定位方式，将盘符、用户目录、临时会话与私有工具等本机路径改为参数或相对路径。

| 档位 | 自足要求 |
| --- | --- |
| portable | 文件引用限定在技能目录内；仓专有名词自带定义或改为通用表述；示例自含数据；外部命令写明安装源、版本与参数 |
| repo-bound | 允许仓内引用；技能内资源通常用相对路径，仓库治理 lint 要求时用完整仓内路径；跨域引用用完整仓内路径；入口「真源」行列明依赖的仓内真源 |

写前自查与改后验证采用 `ops/skills/skill-authoring-governance/references/skill-quality-gate.md`，按本次差异选择证据。
