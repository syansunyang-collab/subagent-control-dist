# change-rationale 触发判例

> 职责：本技能触发的回归基线，竞争性触发验收与漂移修订以此为准。
> 真源：本技能触发判例（正判例、反判例、行为判例）
> 读取：维护读取

## 正判例（该触发，用户真实话术）

1. "这次改动推翻了上次那份决策记录，留一份新的。"
2. "把 executor 的写入权限边界收窄，记一下。"
3. "这个行为变更需要 rationale 吗？"
4. "这条规则别处还在依赖，删掉要写清楚为什么。"

## 反判例（近失配不该触发，注明去处）

1. "把这句提示词换个说法。" → 达不到留档门槛，理由写进 commit message（无技能）。
2. "开一下这个试用开关。" → 试用开关不留档（无技能）。
3. "写一下这次提交的 commit message。" → 日常提交说明（无技能）。
4. "更新 STATUS 的 checkpoint。" → 状态写入，state 政策。
5. "把三个月前那份记录里的结论改成现在的做法。" → 推翻旧决策新建记录写 supersede，本技能 §3。

## 行为判例

1. 达不到门槛就明说不写，理由留在 commit message 或本轮回复。
2. 同一决策的后续改动更新既有记录；记录写当时事实与依据，引用证据路径。
