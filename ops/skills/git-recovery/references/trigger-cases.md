# git-recovery 触发判例

> 职责：本技能触发的回归基线，竞争性触发验收与漂移修订以此为准。
> 真源：本技能触发判例（正判例、反判例、行为判例）
> 读取：维护读取

## 正判例（该触发，用户真实话术）

1. "把工作区改动回退掉。"
2. "刚才那个提交提错了，revert 一下。"
3. "收口提交失败了，卡在 hook 上。"
4. "工作区里有一堆不知道谁改的文件。"
5. "帮我开个分支把这批改动挪过去。"

## 反判例（近失配不该触发，注明去处）

1. "把这轮改动提交了。" → 日常收口提交（无技能）。
2. "看下 git status。" → 现场检查（无技能）。
3. "这个文件的历史谁改的？" → 普通取证 git log/blame（无技能）。

## 行为判例

1. 触发后先分析归属与影响面，再选择修正、回退、revert 或交用户裁决；破坏性操作前核对目标。
2. 回退边界内不误伤他人改动；归属不明的改动先报告再处置。
