# 工具界面设计

> 职责：把工具与管理界面做成使用者能识别、判断和操作的工作面。
> 真源：本技能承载工具界面的实施方法与参考做法；本次任务包提供用户已确认的页面决定与样稿。
> 读取：执行或检查界面任务时读取。

## 1. 接到任务先整理用户要做的事

从任务包的需求、已确认样稿和现有页面提取五项，复用已有内容；缺少且会改变结果的决定随具体选项交回主代理：

- 使用者、当前要完成的一个任务。
- 入口、主要动作、动作完成后怎样看出结果。
- 页面区域与显示字段：每个字段写用户名称、帮助作出的判断、数据来源。
- 本次需要的状态：按真实行为选正常、空、加载、错误、禁用、未保存；写清动作与反馈。
- 已确认样稿、主题、视口或窗口范围；没有既有视觉约定时参考第 4 节做法，并在样稿中展示。

功能混乱的页面，先把功能、表述和展示内容整理成这五项，再画样稿。角色选型按「有哪些角色 → 手里的任务对应谁 → 擅长什么 → 派发」组织；角色配置按「找到角色 → 修改配置 → 保存 → 确认何时生效」组织。两种用途分别给出入口和主要动作。

## 2. 先用真实内容出样稿

新页面或改变信息结构、文案层级的页面，先提交一份静态样稿，使用实际中文、长名称、真实数量级和一处有代表性的异常状态。样稿标明此次改变的区域、主要动作与完成结果，供主代理交用户确认；已有确认样稿的局部修补直接沿用，只呈现有影响的差异。

用户确认样稿后实现对应界面；执行任务若只授权样稿，到样稿交付为止。交付成品时提供同场景对照证据，由主代理组织用户确认成品。样稿确认、模型检查与真实交互分别说明所证明的内容。

## 3. 把显示文案与运行配置分开

为人读的标题、角色介绍、任务类型和状态说明使用独立显示文案；内部键继续用于数据关联。运行配置或模型提示词的描述字段只作为事实材料，按用户任务重写后展示。

- 主页面采用正式名称「角色」「任务类型」；每个输入给可见标题，表格给列头。用户需要比较的同类信息占同一列。
- 主页面显示用户名称和有效信息；内部角色 ID、路由 ID、完整路径、规则章节、提示词原文留在运行数据中。若本次确实要编辑技术标识，先把该用途与入口作为差异交主代理确认，避免借“诊断”扩大显示范围。
- 缺显示名时写可定位的「名称待补」并记录具体数据缺口，保留数据关联键；单条缺文案不阻止其它条目的读取和操作。
- 省略不影响选择的空项；会改变行动的空态明确说明，例如「尚未设置默认模型，选择后可派发」。保存反馈写清「已保存，下一次派发生效」等实际生效时机。
- 运行失败显示动作、原因和恢复动作。技术细节只有在本次需求明确包含诊断入口时才放入该入口；保留原始错误供维护者取证。

采用前后对照：角色卡显示「批量处理／按既定规则处理同类对象」，数据仍使用原角色键；不要把角色键当成介绍。配置冲突显示「配置已在别处更新；重新读取后再保存」，而不是要求使用者理解版本比较协议。

## 4. 视觉：参考方向，不是硬指标

先沿用已确认的主题和组件；面板现有昼夜主题保留，背景装饰不承担状态含义。下列是工具界面的常用做法，按页面实际取舍；偏离时在交付说明里写一句理由。

- 克制：数据工具以内容为主，装饰、动效和品牌化字体不承担信息；一个页面只让一处最显眼。
- 字体：用系统 UI 字族（Windows 下 Segoe UI、Microsoft YaHei UI），同类信息同字号、同字重、同对齐。层级用三四档字号表达，常见取值为正文 14px 左右、辅助 12px 左右、标题再大一两档；不让每个组件各选字号。技术代码才用等宽字体。
- 间距：用一套固定倍数（如 4 的倍数）；同组紧、组间松，区块边缘与表头、表体共用对齐线。
- 颜色：颜色集中在语义令牌（画布、表面、正文、辅助文字、边界、主操作、成功、警告、错误），组件引用令牌；实心按钮的前景与背景成对定义；状态除颜色外还有文字或图形。
- 可读性：正文和控件文字要看得清，参考 WCAG 对比（正文约 4.5:1、大字约 3:1）；渐变或半透明背景上的文字按合成后的实际颜色判断，拿不准就改成实色底。
- 布局：同页上下区块共用内容宽度和左右边缘；文字左对齐，可比较的数字右对齐，操作列位置固定；宽表在所属容器横滚，普通页面不横滚。

动态宽度、图坐标由布局计算，不为清除内联样式破坏数据布局。

WinForms 保留原生控件、系统字体和系统颜色，统一在窗体或共享样式处设置；用 Dock、Anchor、TableLayoutPanel 实现对齐。网页 px 不原样换算成 Font 点数，按目标 DPI 和实际中文显示核对。窗口覆盖任务约定的最小尺寸与 100%、150% 缩放；确认 Tab 顺序、焦点可见、标签完整、按钮可达。不要求把 WinForms 换成网页。

## 5. 本仓面板已定的交互

以下是用户对本仓 agent 面板定过的交互，只在当前页面涉及对应功能时适用；其它界面从任务包与已确认样稿取决定。

- 点开大对象进入独占查看模式：检索条和列表退场；收起后恢复原筛选、选择和位置。
- 一级入口保留高频动作；低频批量操作放抽屉或下拉。
- 依赖图要么完整呈现，要么明确切换为另一种视图。完整图按内容扩展高度，横滚交给外层容器，图内零滚动。
- 每条有效依赖画出可追溯到起点和终点的连线；13 条有效依赖对应 13 条线。数量徽标不替代关系，也不靠「+21」等悬空标签暗示被隐藏关系。数据含不存在的节点时单独说明数据缺口。
- 窄窗口放不下完整图时显示明确命名的列表视图及其依赖信息，或沿用已确认的隐藏方案；不要把无连线节点排列继续称为完整依赖图。

## 6. 按可观察条件自检和交付

围绕本次修改提交「入口／状态／动作 → 可见结果 → 证据」；复用同一次操作的截图与数据证据。网页用现有浏览器驱动，WinForms 用已授权的桌面工具；只清理本次启动的实例，正式使用中的服务保持不动。

必须记录以下事实，即使页面还能点击完成：

- 人话：已约定的人话字段被内部标识、路由标识、规则引用或模型文字替代；输入缺可见标题；控件缺可访问名称；表无列头；首次使用者无法从页面说出当前对象、主要动作、操作结果与恢复方法。
- 状态与反馈：状态只靠颜色区分，或名称与颜色含义冲突；加载、提交、保存缺反馈，保存提示与实际生效范围不符；错误没有恢复动作；禁用没有解释；合同操作无法用键盘到达。
- 版面：同类信息字体或对齐不一致、同页区域边缘不齐、遮挡截断、页面级横滚、文字明显看不清、关键动作不在可达区域。
- 决定兑现：已确认样稿中的主要信息、层级或操作位置在成品中缺失或变化；页面涉及时，第 5 节的面板交互决定未兑现。

每项给具体位置、实际与预期、影响和复现证据。审查者按合同判通过、失败或未验证；纯个人风格偏好列为建议并说明取舍，不伪装成缺陷。无法操作目标时交付已取得的静态证据与缺口，不把静态通过写成真实交互通过。

机械检查适合：可访问名称与列头是否存在、指定文本来源是否泄漏、实色前景背景对比、元素边界与容器滚动、同类计算样式、依赖边与端点数量。语义检查回答：首次使用者是否能从页面说出当前对象、主要动作、操作结果与恢复方法。用户确认承担样稿方向与成品效果；机械检查和模型自评均不代替用户确认。

第 4 节参考值（字号、间距、对比数值）的偏离作为建议提出，写明位置与影响，不单独判为缺陷。

维护本技能的触发或方法时，按 `references/trigger-cases.md` 的判例自检；执行界面任务不需要读它。
