# pi-rail-dispatch 触发判例

> 职责：本技能触发的回归基线，竞争性触发验收与漂移修订以此为准。
> 真源：本技能触发判例（正判例、反判例、行为判例）
> 读取：维护读取

## 正判例（该触发，用户真实话术）

1. "丢给 sol 查一下这个模块。"
2. "让 grok 复核一下这个根因。"
3. "请 astra 看一枪这个方案。"
4. "派个调研，后台跑，好了告诉我。"
5. "子代理交不了卷，一直在重试。"

## 反判例（不该触发）

1. "派三个子代理分头看这几个目录。" → subagent-fleet-discipline（多切片编排）。
2. "用 Claude 的 Agent 起个子代理读代码。" → 原生 Agent 工具，不走 Pi 轨。

## 行为判例

1. 任务提示："让 sol 盘点一下 X，后台等结果。" / 期望首动作：`subagent_prepare` 取模板或直接写种子后 `subagent_dispatch`，随后后台运行 `async_watch.mjs --until-done`。 / 期望产出：退出通知后 `subagent_result`，读报告正文核对再用结论。
