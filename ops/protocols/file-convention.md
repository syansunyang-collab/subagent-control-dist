# 治理文件约定

> 职责：规定治理文件引用、文件头和地图 lint 约定。
> 真源：治理文件引用格式、文件头字段、读取字段值域
> 读取：维护读取

本文件只在新增、修订或审查治理文件引用、文件头、地图工具和 lint 规则时读取。
日常执行任务、派发子代理、消费回执或进入 workflow 时，不因本文存在而额外读取本文。

## 1. 引用格式

治理文件引用必须使用完整仓库相对路径和反引号：

```markdown
`ops/policies/state.md`
`ops/workflows/planning/WORKFLOW.md`
```

优先用“要做什么，读取哪个文件”说明入口；已有上下文直接复用，不重复回指通用规则。仅文件名不足以定位所需内容时引用章节，路径在前，章节在后：

```markdown
`ops/workflows/alignment/state.md §2`
```

根入口文件允许使用文件名：

```markdown
`AGENTS.md`
`PROJECT.md`
`STATUS.md`
`ROADMAP.md`
```

禁止写法：

```text
裸文件名：state.md
相对路径：../policies/state.md
Markdown 链接：[状态](state.md)
无反引号散文提及：见状态策略文件
```

## 2. 文件头

治理 `.md` 文件使用三行文件头：

```markdown
# <标题>

> 职责：<一句话说明本文件唯一职责，最长 50 字>
> 真源：<本文件负责的字段、枚举或规则；没有则写 none>
> 读取：<固定读取 | 命中读取 | 维护读取 | 不作为入口>
```

字段含义：

| 字段 | 含义 |
| --- | --- |
| `职责` | 本文件唯一主职责，用于文件地图和维护定位。 |
| `真源` | 本文件拥有裁决权的字段、枚举或规则。没有裁决权时写 `none`。 |
| `读取` | 主代理读取本文件的入口条件。 |

## 3. 读取值域

| 值 | 含义 |
| --- | --- |
| `固定读取` | 项目入口标记，只用于 `AGENTS.md`、`PROJECT.md`、`STATUS.md` 和 `ROADMAP.md`。宿主已加载的内容直接复用，其余按需读取；不要求每回合重新读盘。 |
| `命中读取` | 当前任务命中 `AGENTS.md`、workflow、policy 或 route 中的入口条件后读取。 |
| `维护读取` | 新增、修订、审查对应规则、字段、工具或模板时读取。 |
| `不作为入口` | 文件只作为生成产物、报告、索引或历史材料存在，不作为主代理入口。 |

## 4. 真源和读取的关系

`真源` 只表示规则归属和冲突裁决权，不表示主代理必须读取该文件。

结合当前任务与已有上下文按需读取；`读取` 字段和流程入口帮助定位，不要求重复读取已知内容。

治理文件中的路径引用只用于建立机器依赖图和定位来源，不授权主代理扩大读取范围。

所需内容位于大集合文件且难以定位时，可写具体章节或字段，例如：

```markdown
`ops/workflows/alignment/state.md §2`
```

章节引用仍只提供定位，不改变读取条件。

## 5. 工具边界

`ops/tools/cockpit_map.py` 生成编排导航产物：`ops/map/cockpit-overview.md`。扫描范围只包含 Codex 编排治理文件和 `layer=orchestration` 的技能；技能归属读取 `SKILL.md` frontmatter 的 `layer`、`domain` 和 `capability_group`。

`ops/tools/cockpit_map.py` 可以检查下列确定性问题：

- 非规范治理文件引用。
- 规范引用指向不存在的文件。
- 文件头缺少 `职责`、`真源` 或 `读取`。
- `读取` 值不在闭集内。
- task-package route 的 `yaml task_package_agent` 固定包头是否存在、唯一，并与 route 文件名和能力提示词路径一致。

执行治理文件约定整改时，`ops/tools/cockpit_map.py --fix-convention` 可以修改扫描范围内的编排治理 `.md` 文件，只允许执行两类动作：

- 补齐 `职责`、`真源` 和 `读取` 文件头。
- 把可解析的治理文件引用改成完整仓库相对路径反引号。

该模式不得删除文件，不得修改非治理产物路径，不得改写规则语义。

工具不判断规则是否合理、真源是否选对、文件是否应删除、业务质量是否通过。
这些判断由主代理或对应审查能力按任务目标完成。

## 6. 扫描和删除边界

引用规范化前先生成基线和扫描报告。
剩余孤儿只表示机器图没有入边，不表示文件无效。
删除孤儿文件前必须单独确认。

修改 `AGENTS.md`、`ops/**` 治理 `.md` 或 `ops/tools/cockpit_map.py` 后，必须运行：

```powershell
python -B ops/tools/cockpit_map.py --lint
```

该命令只作为治理引用、文件头、死链和读取值域守门，不作为业务验收、完成证明或孤儿删除依据。
