# 通用层

> 职责：规定子代理公共执行边界、证据记录和最终回执动作。
> 真源：子代理公共执行边界与通用回执动作
> 读取：维护读取

## §1. 执行

- 以本次 `task_package` 的 `goal`、`scope`、能力合同和 `expected_output` 为准。材料冲突或字段对不上时，记录差异后按任务包明确给出的内容继续；只有真正无法判断且会导致错误结果时才停。必填输入缺失或任务对象不属于本能力时返回 `needs_owner` 并点名缺口。
- 先读任务卡列出的必读材料（`scope.read`）。完成任务需要更多上下文时，按需读取目标工作区内的相关文件，例如调用方、被调用方、配置和测试，并在 `scope_actual.read` 如实列出；凭据文件（token、密钥、密码）不读。业务文件只写 `scope.write`，只删 `scope.delete`。相对写入路径按 `runtime_context.output_root` 解析；优先使用 `resolved_file_path` 和 `resolved_handoff_file`。
- 启动材料包含公共规则、能力规则、补充材料和任务卡；完整任务包在任务卡给出的 JSON 路径。联网取证按任务卡的工具授权执行。根据任务目标选择当前可见工具和方法，遵守本任务的显式工具限制。
- `extensions.orchestration.delegation_intent` 只解释派发目的，不覆盖任务合同。
- 工具输出只提供事实；业务结论由能力判据决定。
- 按当前工具schema填写超时与单位。长命令使用当前可用的受管理后台入口；启动后推进不冲突工作，或结束当前回合等待完成通知，再核对退出状态和产物。入口缺席时，记录命令、日志位置与完成信号，交主代理接续。
- 验证脚本分段保存关键输出；结束时在finally或对应清理中调用本次创建资源的完整关闭入口。临时服务先验证就绪再使用，任务完成后收尾；已存在的正式服务按其维护入口管理。
- 命令失败后先保存关键输出和已完成产物，再围绕一个新假设做有界验证。参数错误先修参数；超时先查输出、进程与已产生文件。同一失败再次出现且没有新证据时，改用独立验证路径；没有可用路径就交付已有成果及具体缺口，由主代理接续。

## §2. 证据

非 evidence-only 任务运行命令时记录命令、工作目录、退出码和能支撑结论的关键输出或产物路径。失败会影响交付时，在报告中写清：

```yaml
command: <实际命令>
exit_code: <退出码或 unknown>
key_output: <关键输出>
impact: <对结论的影响>
next_needed: <缺少的信息或权限；无写 null>
```

事实、推断和建议分开；证据不足时缩小结论，不补写结果。

## §3. 回执

按启动材料给出的提交方式交付。报告与 handoff 字段按以下口径填写：

- `verdict` 只取 `handoff_contract.accept_verdicts`。
- `scope_actual` 记录实际读、写、删的路径，包括任务卡之外补充读取的文件。
- `evidence_refs` 只列真实存在、能支撑结论的引用。
