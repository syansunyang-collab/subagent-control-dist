# 触发与行为判例

## 正判例

1. 把自动裁剪候选接到现在的插件，浅测后导入本机。
2. 裁剪还要靠纯文字回复触发，改成程序自动调度。
3. 新版裁剪包装好了，确认本机加载的是哪份代码。
4. 中途摘要已经完成，却还要等一轮工具才应用，检查接线。
5. 裁剪试用不合适，把本机包和相关配置退回上一份。

## 反判例

1. 裁剪后缓存命中下降了，分析跨轮时序。属于缓存时序分析，不触发本技能。
2. 帮我实现一个通用Pi RPC客户端。属于通用RPC开发，不触发本技能。
3. 只审一下ask_user_question的工具描述。应命中rule-authoring。
4. 重启整个Pi Web并恢复会话。属于宿主重启，不触发本技能。
5. 新建一个仓库技能，检查frontmatter。应命中skill-authoring-governance。
6. 将原生压缩阈值改为另一数值。属于压缩配置维护，不触发本技能。
7. 把裁剪包发布到npm。属于包发布，不触发本地试用流程。

## 行为判例

### 已有充分测试，只做本机导入

任务提示：候选已构建并通过相关测试，做一次浅测后本机试用。
首动作：核对当前包来源、候选哈希和已有证据，读取local-trial资源。
产出：浅测范围、私有备份、逐项导入清单、新实例实际加载证据；不自动扩成收益矩阵。

### 工具被宿主重新开放

任务提示：自动裁剪模式中仍看到了context_prune工具。
首动作：同时检查实际工具列表、任务开始后的工具选择、静态工具文案和执行结果。
产出：定位到宿主选择或插件执行层；自动模式返回管理状态，不引入新的用户审批。

### 只确认当前安装

任务提示：只读确认自动裁剪是否导入，保留所有运行实例。
首动作：读取选中的包入口、裁剪配置及已有加载记录。
产出：磁盘选择、包哈希、实例证据及尚未核对的旧实例范围；不把磁盘修改当成所有会话已经更新。
