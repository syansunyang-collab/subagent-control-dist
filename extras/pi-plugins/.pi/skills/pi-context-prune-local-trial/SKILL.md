# 裁剪接线与本机试用

> 职责：将裁剪候选接入程序生命周期，验证后导入本机并说明实际生效范围。
> 真源：候选包源码和本机实际配置；本技能的references/local-trial.md；ops/skills/rule-authoring/SKILL.md；tools/render-pi-global-system-tail.mjs。
> 读取：命中加载

## 首动作与资源路由

读取当前包选择、裁剪配置、候选Git状态和已有验证证据，区分用户要求的接线、浅测、导入或回退范围。

- 执行接线、加载检查或导入时，读取 `references/local-trial.md`，产出模式映射、导入清单及对应证据。
- 修改技能触发或核对覆盖面时，读取 `references/trigger-cases.md`，判断受影响正反判例与行为路径。
- 修改模型可见文案时，使用 `ops/skills/rule-authoring/SKILL.md` 核对实际组合文本；只处理本次变化的消费面。

## 接线判断

把midRun.enabled（中途程序调度开关）与pruneOn（常规收尾触发方式）分开说明。沿用候选已有配置定义，写清受影响组合的调度主体、提示注入和工具行为。

在工具回合结束时准备摘要，在context钩子消费已就绪且仍满足阈值、间隔和范围条件的计划。请求边界只应用已有结果，摘要与存根同次进入请求。原文保留到有效摘要可交付，回查继续使用context_tree_query。

将取消、分支切换、原生压缩及摘要参数变化接到计划失效机制。复用原有索引、持久化与重复范围处理，确认关闭中途功能后的兼容路径。

检查模型实际可见的工具description、promptGuidelines和系统追加段。自动模式的调度责任留在程序；模型驱动模式的周期引导只留在对应模式。宿主误开放工具时，以真实管理状态响应，保留用户手动命令入口。

## 验证与试用

先复用已有有效测试，仅补本次新增接线、消费时机或配置组合。把以下证据分开记录：

1. 构建与包内容检查。
2. 摘要、存根与回查的程序机制检查。
3. 实际SDK或provider请求中的内容交付。
4. 本机新实例加载路径、配置和提示。
5. 主模型行为与收益观察。

用户要求浅测时，选择能区分本次关键故障的一次小样本；使用隔离配置和内存设置。降低测试水位时记录测试值，部署值仍取获授权配置。失败后保留原始结果，定位层级再决定修补，避免为获得通过标签重复样本。

## 导入与恢复

导入前列清包版本或提交、构建哈希、配置差异、提示差异、保持不变的部分和旧实例处理范围。使用现有打包命令，将已测产物放到稳定的本地包目录，更新单个包选择。

备份受影响文件到用户私有目录，修改目标字段并保留其他设置。仅在程序接管通过后减弱原有提示触发要求；风格正文从唯一源生成。

新实例验证通过后报告其范围。旧实例按其实际重载状态说明，独立处理；需要中断运行任务才能重载时，先取得该中断的授权。

回退时还原本次包选择和对应配置字段。发现这些字段已被后续任务修改时，核对差异归属后再恢复。将认证材料留在现有认证入口，证据仅记录非敏感配置与哈希。

## 收口

交付实际导入清单、浅测结果、加载证据、备份位置和未验证范围。将版本、会话和本次日志放入验收记录；技能保留可复用的决策与操作方法。
