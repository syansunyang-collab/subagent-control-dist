# 本地 Pi 插件开发触发判例

> 职责：区分本地插件工程、技能写作、专项维护与普通工具使用。
> 真源：本技能正反判例和行为验收基线
> 读取：维护或校验技能触发时

## 正判例

1. 「写个本地 Pi 插件，帮我管理稍后要做的任务。」
2. 「这个插件别再往 node_modules 打补丁了，重构成自己维护的包。」
3. 「做个 Pi 扩展，给模型提供两个工具，写完装到本机验证。」
4. 「插件已经有源码了，帮我把加载、卸载和升级这条链补齐。」
5. 「把这个插件从只在 TUI 能用，改到 Pi Web 也能正常运行。」

## 反判例

1. 「帮我写一个教代理开发插件的 skill。」→ skill-authoring-governance；交付物是技能，不是插件。
2. 「只审这几个工具的 description，看看模型什么时候会调用。」→ rule-authoring。
3. 「写个程序通过 Pi RPC 驱动会话，不做扩展。」→ use-pi-rpc-safely。
4. 「pi-web-access 搜索供应商配置怎么改？」→ pi-web-access-operations。
5. 「核对裁剪候选包的自动接线，导入本机试用。」→ pi-context-prune-local-trial。
6. 「重启 Pi Web，恢复刚才的会话。」→ restart-pi-web-windows。
7. 「十分钟后提醒我看看构建结果。」→ 无本技能；使用可用的调度工具。
8. 「给这个 WordPress 插件加一个菜单。」→ 无本技能；按目标产品开发流程处理。

## 行为判例

1. 「做一个 Pi 本地扩展，稍后叫醒代理，别刷屏。」→ 首动作：核对宿主版本、加载入口及忙闲语义。产出：任务选择正反例、忙时事件合并合同、最小包与真实宿主投递证据；事件合并由实现保证。
2. 「已有源码，Windows 和 Pi Web 都要能跑，验证后替换旧插件。」→ 首动作：区分源码、安装包、当前实例和旧任务。产出：隔离验证、宿主检查、经授权的安装替换及恢复办法；加载成功与业务完成分别报告。
3. 「工具说明留英文，给我翻译看看它怎么指导模型。」→ 首动作：读取注册时的实际组合文本和对应行为。产出：英文模型接口、中文译文、触发条件与默认值核对；不因翻译请求改变源码语言或工具名字。
