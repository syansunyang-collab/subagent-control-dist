# 模型接口检查

> 职责：将插件能力转成模型能正确选择、调用和消费的接口。
> 真源：插件实际注册文本、schema、实现和本文件检查步骤
> 读取：新增或修改工具、模型通知及参数时

## 从判例到入口

先写本次工具的 2–3 个正例、2–3 个容易误用的近邻反例，以及每例期望的首动作。包含用户明确提出的需求和代理推进任务时自行遇到的需求。反例写明实际去处，例如立即执行工具、已有完成通知或相邻工具。

根据判例写入口，再用同一组判例核对文本。例子用于界定能力，不把工具定义成只能接受示例措辞。将触发判定写在调用前可见的 description；正文里的操作指南不能替代入口发现性。

## 文本落位

| 槽位 | 内容 | 核对方式 |
| --- | --- | --- |
| description | 什么任务或状态下使用、产生什么结果、容易混淆的相邻路径 | 对照正反例，确认既不漏用也不误用 |
| promptSnippet | 简短用途索引 | 与 description 保持相同边界，不复制完整合同 |
| promptGuidelines | 当前任务特有的调用顺序或跨工具选择 | 删除后是否会改变正确操作；可推导常识省略 |
| 参数 schema 与说明 | 必填关系、默认值、范围、单位、时区及相邻字段区别 | 与解析、校验和实际执行逐项比对 |
| 返回与错误 | 实际完成阶段、具体缺口和可执行下一步 | 已登记、已投递、已执行和业务完成分别表达 |
| 异步通知 | 事件来源、任务标识、最新状态与跟进所需信息 | 标注命令输出等数据，消息裁剪后保留身份和结果 |

参数服务常用任务。删去没人需要的别名；不同操作的专属字段按用途分组或拆成工具。声明字段互斥、忽略或条件必填时，优先调整 schema 和实现，使模型不用猜优先级。

## 引导与实现

模型提示词保持英文；向用户解释时提供中文译文。按请求区分翻译、文案修改和改名，改名同时检查 schema、通知、文档和直接调用方。

先教正确使用，再用一个明确的近邻边界排除误用。使用条件与调用顺序分别表达：“需要稍后跟进”决定是否用，“当前工作完成后交接”决定何时调用。已有完成通知与额外轮询之间的取舍属于入口引导。

背景已经在会话中时，参数只要求下一步动作或必要标识。命令输出是结果数据，定时通知是系统事件，均不伪装成新的用户指令。

去重、忙时合并、取消、并发领取和重启恢复由代码实现。提示词只解释这些行为的范围；不能把“请勿重复”当作幂等保证。取消时分别说明尚未投递事件、宿主已收消息、运行中进程和未来执行的处理。

## 验证产物

通过插件的实际注册入口收集工具名、description、schema、用途摘要、指南和通知样本。按本次判例人工核对组合文本；需要独立触发证据时，在干净上下文提供真实工具列表及未标注答案的话术。

功能测试验证机制，模型选择测试验证发现性，两者不互相替代。交付说明实际采用的方法、修正的差异与仍影响使用的缺口。
