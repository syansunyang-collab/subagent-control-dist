# 本地 Pi 插件开发

> 职责：从应用需求完成本地 Pi 插件实现、模型接口设计、宿主验证和安装交付。
> 真源：目标版本 Pi 源码与文档、插件源码；模型规则依赖 ops/skills/rule-authoring/SKILL.md
> 读取：命中插件开发或重构任务时

## 首动作

明确用户要的功能、使用入口和完成证据。检查工作区与改动归属，再核对 Pi 版本、现有包版本、仓内源码、实际安装位置、配置加载来源及活动宿主。已有有效证据直接复用。

先找官方示例和现有实现，核对版本与适用性后复用。分别判断问题出在插件核心、工具接口、宿主适配还是安装配置；局部能修复就局部改。需要独立维护时把实现放进受版本管理的插件包，依赖、入口和验证命令一起交付。

## 按阶段读取

资源路径相对本技能目录；入口直接到达对应资源。

| 情况 | 读取 | 产出 |
| --- | --- | --- |
| 设计或修改工具字段、选择时机、异步注入 | references/model-interface.md | 正反判例、实际模型可见文本和字段行为核对 |
| 运行测试、宿主适配、安装迁移或卸载替换 | references/host-validation.md | 所改消费路径的证据、生效范围及恢复办法 |
| 修改技能入口或核对相邻技能 | references/trigger-cases.md | 触发与首动作判例核对 |

新增或修改模型可见文字时按 ops/skills/rule-authoring/SKILL.md 审查；本技能只承担插件工程里的执行顺序，不复制规则判据。

## 实现与交付

1. **形成最小合同。** 写清触发条件、输入、输出、副作用和宿主生命周期。异步功能额外区分已登记、待投递、已执行与完成；取消、去重和恢复语义以代码可保证的范围为准。
2. **先定模型入口。** 用真实用户话术和代理自主推进场景写正反例，再确定工具名、description 和必要字段。调用时机与调用顺序分别表达；简单用途用工具入口，复杂多步方法再考虑配套技能。
3. **完成有界实现。** 复用官方注册示例与适用依赖，把业务状态和宿主接线分清；只为实际多进程、忙闲切换和资源持有场景增加机制。配置接口和平台差异由正式实现承载。
4. **验证直接消费路径。** 从参数解析、核心行为走到实际加载与本次涉及的宿主入口。模型说明使用英文，给用户提供中文解释；检查实际注册文本和通知，而非仅阅读 README。
5. **按授权切换。** 开发验收与在线生效分别确认。持久安装时先审迁移和旧任务，切换后核对工具清单与实际调用，保持其他插件及用户配置不变。
6. **按结果收口。** 说明功能与源码位置、验证证据、当前生效状态和剩余缺口。失败先定位层级；隔离验证不通过时继续修复候选版，环境授权缺失时只收口候选产物并说明所需决定。

## 完成标准

模型可从工具入口判断何时使用、怎样填参数和如何消费结果；实现与文案中的默认值和承诺一致。用户要求的入口有相应运行证据，未验证项按实际影响说明。交付源码、依赖与测试可复现，安装及恢复步骤可操作；补丁残片、一次性日志和个人环境路径不混入插件接口。
